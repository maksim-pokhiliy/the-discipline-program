## Detail on the live ones

**PAC-1 (the migration — SPEC'd W2, owner-gated run).** W2 flipped the `byProfile` VO to the union; legacy free-string loads (`axes:[{name,values}]`) are now invalid until backfilled (aggressive cut, no both-shapes bridge — owner rules `aggressive-migration-no-bridge` / `migration-intermediate-velocity`). **Dev has ZERO byProfile loads** (`seed.ts` = users+profiles only, memory `seed-architecture`), so dev needs no backfill — the intermediate-red is the accepted aggressive path. The **prod** probe + backfill are an OWNER-GATED step (do NOT connect to prod from this work; author the script only on a non-empty probe).

- **Probe (owner runs against prod).** Correct table = `training_schema_rows` (verified `schema.prisma:696` — research's `app_schema_rows` was WRONG; the `load` Json column lives on `training_schema_rows`):
  ```sql
  SELECT id, load FROM training_schema_rows WHERE load->>'kind' = 'byProfile';
  ```
  Prisma equivalent: `prisma.schemaRow.findMany({ where: { load: { path: ["kind"], equals: "byProfile" } } })`.
- **Backfill map (per legacy load's axis `{name, values}`) — REVISED for design A (D-7); the union arms below are superseded by the flat `{axisId,label,values,binding}` snapshot.**
  - `name` ∈ {gender, sex} (owner judgment) → snapshot the SYSTEM Gender row: `{ axisId:"cgender000000000000000000", label:"Gender", values:["Male","Female"], binding:"GENDER" }` (verify the legacy values map to Male/Female; the athlete then resolves from the typed column, no pick).
  - else → find-or-create a `ProfileAxis` by `key`/`label` matching `name` (create from `{ key:name, label:name, values }` if none — created rows are `binding=null`) → `{ axisId, label, values, binding:null }` (snapshot from the catalog row).
- **Properties.** Idempotent (run once); tolerate-orphan (PAC-9 — no FK; the snapshot keeps the load functional). Because the catalog denormalizes label+values+cells, the rewrite is purely additive. The matching W3 step re-keys `profileSelections` (PAC-2).

(PAC-7 — the four-projection gate — is now CLOSED: `four-projection-recheck.md` PASSED + the plan-editor-compose `D-BYPROFILE-AXIS` cross-ref RATIFIED.)

**PAC-8 / PAC-9 (W1 → W2 hand-off — CLOSED by the W2 design).** Both dissolved as a BENEFIT of the denormalize + bind-by-`axisId` design (gate §7), not by adding machinery:

- **PAC-8** — the byProfile load no longer free-types axis values; catalog values are a snapshot of the catalog's already-`normalizedString` (NFKC + zero-width-strip) values, so the catalog's NFKC law is the single law (`load.ts`'s bare `.trim()` is defensive only). The find-or-create picker binds by `axisId` (cuid), NOT `key`/`label` string → a `level`/`Level` split is two visible, distinct rows the coach chooses between, never a silent fork. No `keyLower` needed (D-4 carry-forward closed).
- **PAC-9** — TOLERATE-ORPHAN. No FK (D-2). Because the load denormalizes label+values+cells, a deleted axis leaves the referencing load fully RENDERING (snapshot label) and RESOLVING (cells + selection by `axisId`); the only losses are re-pickability + an orphan-labeled analytics group. No restrict-on-reference, no reference-scan-on-delete.
