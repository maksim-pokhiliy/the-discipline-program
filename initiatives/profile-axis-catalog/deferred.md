Owner default (2026-06-22): keep masters a custom catalog axis; do NOT add a `dob` human attribute until auto age-resolution is actually needed. Revisit if Denys runs age-based load routinely.

**PAC-8 / PAC-9 (W1 → W2 hand-off, from W1 QA).** W1's catalog validates STRICTER than the surfaces it will later feed: values go through `normalizedString` (NFKC + zero-width strip) where `load.ts` uses a bare `.trim()` (QA-007), and `key` is case-sensitive with no `keyLower` (D-4 / QA-004). When W2 wires the catalog into the byProfile picker it must (PAC-8) pick ONE normalization + case-fold law for both surfaces, and (PAC-9) decide the axis-delete referential policy — W1 has no FK to the catalog, so today delete is always safe, but once a load references an axis a delete silently orphans the reference (QA-008). Both are W2 design items, not W1 bugs (`git diff` proves zero W1 coupling to `load.ts`/resolver).
