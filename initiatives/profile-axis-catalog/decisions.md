### D-1 — Two-category ontology: human identity vs training classification

- **Status:** RATIFIED (owner, 2026-06-22 — "вопрос семантики и честности").
- **Decision.** An athlete's attributes split into two categories that are NEVER merged:
  - **Human identity** — gender (and height, weight, health). Natural/intrinsic; exist independently of whether any coach ever programmed anything. Stay TYPED columns on `AthleteProfile`. Rendered in the profile's _human_ card; always editable regardless of the catalog.
  - **Training classification** — level, scale, masters-division, weight-class. Exist ONLY because a coach differentiates load by them. Free-form CATALOG axes. Rendered in the profile's _athletic_ card.
    The athlete profile is two layers, not one flat "list of axes."
- **Rationale.** Owner caught the smell in the first design (gender-as-an-axis-in-the-shared-catalog): gender is about the athlete-as-human, level is about the athlete-as-athlete; collapsing them makes "can the athlete state his sex" hostage to whether a catalog axis exists — a corrupt model, and one where a coach editing the catalog could rename/delete the values of "sex." The split keeps identity intrinsic + protected while keeping classification flexible.
- **Links.** Supersedes the first-pass "bound-axis in a shared catalog" sketch. Builds on athlete-core `D-FIELDS-GENDER-INERT` (gender stored, not yet wired) + `D-PROF-SELECTIONS-HONEST` (no fabricated catalog).

### D-2 — Profile axis = first-class catalog entity; freedom via find-or-create

- **Status:** RATIFIED (owner, 2026-06-22).
- **Decision.** A training-classification axis becomes a first-class catalog row — `ProfileAxis { id, key @unique, label, values String[] }` — edited via the admin console like labels and exercises. Coach freedom (axes are NOT a closed enum) is preserved via **find-or-create**: in the load-editor the coach types an axis name and either picks an existing catalog axis (gets its id) or creates a new one on the fly (like labels here / tags in Linear). Values are a controlled `String[]` on the axis — ONE source for both the coach's `cells` and the athlete's pick (no re-typing). Catalog is GLOBAL (single-coach project; owner-scoping deferred PAC-5).
- **Rationale.** Today an axis has NO identity — it lives as bare strings inside one row's `byProfile` load, joined to the profile by the string `axis.name`. That join is a footgun (`D-PROF-SELECTIONS-HONEST`: "a typo 'Rx' vs 'RX' silently breaks load resolution") and spawns duplicate axes ("level" vs "Level"). Identity fixes the join, kills dupes, and UNLOCKS the curated profile picker that D-PROF-SELECTIONS-HONEST had to cut for lack of a catalog.
- **Links.** athlete-core `D-PROF-SELECTIONS-HONEST` / `D-PROFILE-SELECTIONS`; admin labels/exercises CRUD as the pattern.
- **Acted.** W1 shipped the `ProfileAxis` model (`app_profile_axes`) + contract `@repo/contracts/coaching/profile-axis` + api-server `profileAxisAdminApi` + admin "Profile Axes" CRUD module per this (2026-06-22, `feat/profile-axis-catalog-w1`). Refined by D-4 (case-sensitive `key`) + D-5 (placement).

### D-3 — byProfile axis = discriminated union (catalog | human); resolver branches by kind

- **Status:** ⚠️ **SUPERSEDED by D-7 (design A, 2026-06-23).** The discriminated-union SHAPE (`{kind:"catalog"} | {kind:"human"}`) is replaced by a single `binding`-discriminated object — the union left gender authorable TWO ways (the `human` arm AND a coach-made catalog "Gender" axis), the hole owner smoke exposed. The four-projection RATIONALE below (free-string axis = name-collision; gender must resolve from the typed column; cells/cap preserved) STANDS and is carried forward by D-7. Originally: RATIFIED (W2 gate, 2026-06-22) — concept owner-APPROVED 2026-06-22; gate (four-projection re-check + plan-editor-compose cross-ref) DISCHARGED. See `four-projection-recheck.md` Part A for the union analysis, Part B for the design-A supersession.
- **Decision.** A `byProfile` load axis becomes a discriminated union (`z.discriminatedUnion("kind", …)` — the codebase-native pattern):
  - `{ kind:"catalog", axisId, label, values }` → resolves from `profileSelections[axisId]`; `label`+`values` are a **denormalized snapshot** of the catalog row at authoring time (keeps the `superRefine` + every render/picker a pure function of the load; the resolver never reads `ProfileAxis`).
  - `{ kind:"human", attribute:"gender" }` → resolves by reading the typed `AthleteProfile.gender` column via a LOCAL inline `MALE|FEMALE → coord` map; **NO denormalized values** (the closed `attribute` implies the fixed const `GENDER_AXIS_COORDS = {MALE:"Male", FEMALE:"Female"}`), which structurally locks the human arm to the gender vocabulary. `attribute` is a CLOSED enum, `GENDER`-only (weight resolves via bodyweight/percentage; height doesn't differentiate). `gender = null` → unresolvable, **no pick offered**.
    The resolver branches by `kind`. Write-back is symmetric: a human-axis pick writes the `gender` column (W3), a catalog-axis pick writes `profileSelections` by `axisId` (W2 inline picker + read; W3 profile-card + bulk migration).
- **Four-projection verdict (the gate).** PASSED. The **current free-string axis `{name, values}` is a latent NAME-COLLISION** — `name:"gender"` (resolve from the typed column, group by intrinsic identity) vs `name:"level"` (resolve from a manual pick, group by mutable classification) is "depends what was meant" in the EXECUTE and ANALYTICS projections. D-3's union is the lens-MANDATED split on `kind` — the inverse of confirming a primitive, structurally identical to `D-LADDER` (one `steps` field → two primitives because it collided in analytics). Each arm means one thing across all four projections; the `kind` discriminant + disjoint identity-space (cuid `axisId` vs closed `attribute`) clear the cross-arm collision; D-1 holds (gender resolved in exactly one place — the human arm). Full per-arm × per-projection table in `four-projection-recheck.md` §4.
- **OQ resolutions (gate).** Encoding + denormalization → §5; find-or-create UX = kind-first authoring → §6 OQ-2; profileSelections re-key cut = W2 reads by `axisId` / W3 owns write + bulk migration, intermediate-red stated → §6 OQ-3; human coord values = `Male`/`Female` lms-local → §6 OQ-4. **PAC-8** (normalization/case-fold) + **PAC-9** (axis-delete = tolerate-orphan) resolved as a benefit of denormalize+bind-by-`axisId` → §7.
- **Supersedes (cross-ref, not a deep-edit).** Revises primitive-v2 `D-V2-PROFILE-NESTING` (#17, `reshape-design.md` §2.5) — free-string axis → discriminated union; cells (coords/kg) + the 1–2 axes cap preserved. primitive-v2 §2.5 scoped #17 to authoring+render with "no live reader (resolver is Phase 3)"; W2 is that Phase-3 wiring. primitive-v2 is CLOSED — forward cross-ref only.
- **Links.** `four-projection-recheck.md` (the gate analysis); plan-editor-compose `D-PERSIST` + the new cross-ref entry (sacred VO); contracts `lms/_shared/load.ts`; athlete-core `D-FIELDS-GENDER-INERT` (named this exact fix). Discharges PAC-7; sets up PAC-1 (W2 migration probe) / PAC-2 (W3 selections re-key).

### D-4 — W1 `ProfileAxis.key` is case-sensitive `@unique` (no `keyLower` mirror)

- **Status:** RATIFIED (owner, Gate A 2026-06-22).
- **Decision.** W1's `ProfileAxis.key` carries a plain case-sensitive `@unique` constraint — NO derived `keyLower @unique` column (unlike `Label.nameLower` / `Exercise.canonicalNameLower`). `level` and `Level` are therefore two distinct catalog rows. The shared `normalizedString` (NFKC + zero-width strip + trim) applies to `key`/`label`/values inputs but does NOT lowercase.
- **Rationale.** `key` is a deliberately-typed machine slug (the admin chooses it), not free-typed prose; case collisions are a low-probability admin-discipline edge, not the athlete-facing footgun. The dupe D-2's rationale names ("level vs Level") is killed primarily by W2's find-or-create — the coach picks the one canonical catalog row instead of free-typing — so a within-catalog case-fold is a W2 concern, not a W1 model requirement. Simplest-correct for W1; `keyLower` is a cheap, reversible add later.
- **Carry-forward.** If W2's `byProfile` picker keys off `axis.key`, a `level`/`Level` split silently forks the controlled vocabulary → decide case-folding (`keyLower @unique` + derivation) when wiring W2. See `deferred.md` PAC-8.
- **Links.** design.md MD-3 / OQ-1; qa.md QA-004 (awareness flag). Refines D-2.

### D-6 — W2 execution calls (the load-bearing implementation decisions)

- **Status:** RATIFIED (owner, Gate A 2026-06-22; built + reviewed + QA'd on `feat/profile-axis-catalog-w2`).
- **Why this exists.** D-3 ratified the union + the OQ resolutions; the W2 BUILD then made four load-bearing implementation calls (`.feature-dev/1782147320/design.md` DR-1..DR-4) plus an owner-approved Gate-A scope expansion (R3). Per the promotion rule these must not live only in the gitignored `.feature-dev/` — distilled here. Full analysis: design.md §6; the sacred-VO sign-off: `four-projection-recheck.md`.
- **Decisions:**
  - **(DR-1) Two distinct unresolved arms + the field rename.** The resolver distinguishes `missing_profile_pick` (≥1 **catalog** axis unpicked — INLINE-fixable; the athlete-session offers the inline picker) from `missing_profile_attribute` (a **human** axis whose `gender` is null — profile-fixable, `attribute:"gender"`, NO inline pick, a "set your sex in your profile" steer). Distinct affordances + distinct fix-locations ⇒ a discriminated-union split, not an optional flag (manifesto 2.3). On a MIXED unresolved load the **catalog pick surfaces FIRST** (inline-actionable) — `missing_profile_attribute` only once every catalog axis is picked. The all-human **cell-miss** also steers (returns the attribute arm, not an empty-`axisLabels` pick) — review CODE-002 / qa QA-001 fix. `ResolvedLoad.axisNames`→`axisLabels` (the field now carries per-axis LABELS, not free names) — honest-rename, **no external consumer** (apex is the separate legacy Spring app, memory `project-domain-architecture`; this wire is produced only by the api-server resolver, consumed only by apps/platform).
  - **(DR-2) Platform `ProfileAxis` GET+CREATE chain mirrors the lms-label chain.** A new `profileAxisPlatformApi.{list,create}` next to W1's admin api (`coaching/profile-axis.ts`); LIST orders `label asc` (picker) vs admin's `createdAt desc`. A shared module-local `createProfileAxisRow` is extracted (rule-of-two: admin + platform create now both call it — manifesto 2.1; P2002→`ConflictError({field:"key"})` + `handlePrismaError` shared). **Dual role-gate** (defense-in-depth): `withCoachAuth` at the route + `requireCoachLikeRole` inside the api method (mirrors the platform-label sibling). **No dep-cruiser edit** — platform→`@repo/api-server/coaching` is already an allowed edge.
  - **(DR-3) The unbound catalog axis = `{kind:"catalog", axisId:"", label:"", values:[]}` held in the live `Load`.** It is shape-valid TS (`axisId: string`) but rejected at save by `.cuid()`/`.min(1)` → the coach-prose `profileAxisPick` message ("Pick an axis for this dimension"). This is the compose draft→strict-on-save precedent (plan-editor-compose D-10.4-S2) at **zero blast radius**: `RowFormState.load` stays `Load | null` — NO `ByProfileDraft` type widening (rejected as A8, overkill — the byProfile draft diverges only by an empty `axisId`, unlike compose's structurally-distinct draft).
  - **(R3 — owner-approved Gate-A scope expansion) FULL inline find-or-create, not pick-only.** The coach gets a values form (name + `TagsInput`) inside the load editor — types a new axis name, fills ≥1 value, creates. The create writes to the catalog SSOT via `useCreateProfileAxis` (`POST /api/platform/profile-axes`) and binds the **server response** (`{id, label, values}`), NOT the raw typed input — so no NFKC divergence between the catalog row and the load snapshot. `CreatablePicker.onCreateOption` returns `null` and instead reveals the inline form (the "like labels" template diverges here — labels create from a bare name; an axis needs values).
- **The denormalized snapshot is WHY PAC-8/PAC-9 are closed.** The catalog arm carries `label`+`values` (a point-in-time snapshot); the human arm carries none (const-locked). This keeps the resolver + the `superRefine` + every render a **pure function of the load** — no `ProfileAxis` read (boundary + the athlete hot path stay clean). Consequence: binding is by `axisId` (cuid), so a `level`/`Level` catalog split is two visible rows, never a silent fork (PAC-8 closed); a deleted axis leaves the referencing load fully functional off its snapshot (PAC-9 = tolerate-orphan). See `four-projection-recheck.md` §5/§7. **Revised by D-7 (design A):** the snapshot now denormalizes `binding` (not `kind`); the `human` arm is removed (gender = a `binding=GENDER` catalog row that ALSO carries the `label`+`values` snapshot — `["Male","Female"]`); the resolver branches on `binding`. The pure-function-of-the-load invariant is unchanged; the denormalized field set grows by one (`binding`).
- **Links.** design.md §5/§6 (DR-1..DR-4, A8 rejected) + §9 OQ; `four-projection-recheck.md` (the gate; §5 VO shape, §7 PAC-8/9); D-3 (the ratified contract this executes); review.md (CODE-002 fix) + qa.md (QA-001). ### D-7 — W2 REVISION (design A): gender = one SYSTEM, PROTECTED, `binding`-bound catalog axis

- **Status:** RATIFIED (owner approved design A in concept 2026-06-23; this records the execution calls, as D-6 did for the union). **Supersedes D-3's discriminated-union shape**; revises the D-6 snapshot note. D-1 / D-2 / D-4 / D-5 unchanged.
- **Why this exists.** Owner smoke found the union's hole: nothing stopped a coach creating a `kind:"catalog"` axis literally named "Gender" (M/F) and assigning THAT — it resolved from `profileSelections` (a manual pick), ignored the typed `gender` column, and a `gender=MALE` athlete got "pick your gender" (values mismatched too: catalog `M`/`F` vs the human arm's `Male`/`Female`). The `human` arm was bypassable → two parallel ways to express gender = the "gender lives a separate life" disease (D-1) via the catalog door. The four-projection re-check had PASSED the union but MISSED the AUTHORING (coach-SETS) projection's dual gender path (Part A §4 wrongly called it a hygiene smell). Full re-analysis: `four-projection-recheck.md` Part B.
- **Decision (the new contract).**
  - **(D7-1) `ProfileAxis` gains `binding ProfileAxisBinding?`** (enum `{ GENDER }`, nullable) **+ `@@unique([binding])`.** Postgres unique-on-nullable allows unlimited `null` bindings but AT MOST ONE `GENDER` — a second gender-bound axis is rejected by the DB, by construction (the owner's "close the dup BY CONSTRUCTION").
  - **(D7-2) Exactly one SYSTEM, PROTECTED Gender axis** — reserved `key`, `label "Gender"`, `values ["Male","Female"]`, `binding GENDER` — inserted by the W2 migration. The migration is the existence SSOT (prod runs `migrate deploy` with NO seed; dev `migrate reset` re-applies it). Protected: `binding` is omitted from the create/update form schemas (not API-settable → no second `GENDER` authorable); CRUD rejects edit/delete of any `binding != null` row; the reserved `key @unique` blocks a key-collision dup. (Existence mechanism = migration insert over seed/ensure-on-startup — the owner left this to engineering; chosen because it is the only one that reaches prod.)
  - **(D7-3) byProfile axis = a SINGLE object `{ axisId, label, values, binding }`** — the `kind`-union is REMOVED, the `human` arm is GONE; gender is now a catalog row distinguished only by `binding`. The snapshot denormalizes `binding` so the resolver stays a pure function of the load (D-6 invariant + one field). `superRefine`: per-axis value-dedup, value-set, and distinct-axes (by `axisId`) now apply uniformly — every axis carries `values` + `axisId`. Shape is a flat `z.object`, not a `z.discriminatedUnion` (the discriminant is a field value, not a structural split) — simpler than the union.
  - **(D7-4) Resolver branches on the snapshot's `binding`:** `GENDER` → read the typed `AthleteProfile.gender`, map enum→coord via a LOCAL inline map (`api-server-lms-no-coaching`), no pick; `null` → `profileSelections[axisId]` (as the union's catalog arm did). The two unresolved arms (D-6 DR-1) re-expressed on `binding`: `missing_profile_pick` (a `binding=null` axis unpicked — inline-fixable) vs `missing_profile_attribute` (a `binding=GENDER` axis with `gender=null` — profile steer, no inline pick); a mixed unresolved load surfaces the pick FIRST. `ResolvedLoad` arms + the `axisLabels` field unchanged.
  - **(D7-5) Authoring = ONE catalog picker** (the kind toggle is dropped). The system Gender axis appears in the picker list, marked "profile attribute". Picking it binds its snapshot incl. `binding:"GENDER"`; values lock; cells seed from its canonical values; the athlete makes NO pick for it. A coach-created (inline find-or-create) axis is always `binding=null`.
- **Single-path (the property design A guarantees).** A gender differentiation = `binding=GENDER`, authorable exactly once (the protected system row) and a second impossible (`@@unique([binding])` + not API-settable). A coach-named "Gender" _plain_ axis is `binding=null`, a manual-pick training axis that never touches the typed column — not a gender differentiation, cannot masquerade as one (the resolver reads the column ONLY for `binding=GENDER`). Label-text is deliberately not policed (brittle: Sex / Sexe / М-Ж); the invariant is the `binding`.
- **Consequences.** Simpler than the union (one object, not two shapes); D-1 now holds at AUTHORING, not just resolution; the snapshot + the catalog row grow one field; a migration data-insert + a new DB unique index (surfaced at Gate A); the system-axis `values` ↔ resolver `GENDER_AXIS_VALUES` coupling is pinned by a test (the two ends of the enum→coord contract). PAC-8/PAC-9 stay closed (denormalize + bind-by-`axisId` unchanged). PAC-1's backfill map gets one tweak: a legacy `name ∈ {gender,sex}` load now backfills to the system Gender `axisId` (not a removed `kind:"human"` arm).
- **Reversibility.** Two-way for the VO/resolver (revert the branch). The migration (column + unique index + insert) is a forward step — rollback = drop the column/index; loads referencing the system axis revert to plain pick (tolerate-orphan, PAC-9).
- **Links.** `four-projection-recheck.md` Part B (the gate — the single-path authoring fix); `plan-editor-compose` `D-BYPROFILE-AXIS` (revised cross-ref, sacred-VO re-sign-off); supersedes D-3 (union); revises D-6 (snapshot carries `binding` not `kind`; `human` arm removed); D-1 (gender typed column — unchanged, the bound axis READS it); athlete-core `D-FIELDS-GENDER-INERT` (the named fix — now closed by a single path).
