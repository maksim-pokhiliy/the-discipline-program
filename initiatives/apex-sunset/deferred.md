- **AS-4.** The publish RESULTS/status UX carry-forwards were born against the connector but describe our own UI — most survive the mechanism swap (snapshots make some easier: e.g. MP-25's "partial week" gains an honest source of truth). Sweep `mobile-publish/deferred.md` at P4.2 with the snapshot model in hand.
- **AS-5.** Guiding line: delete what existed only because legacy was a foreign black box (cipher, reconnect, adapter, retry-vs-409 emulation); keep what expresses the coach's intent (links as publish targets, the published-day ledger extended into snapshots per D-4).
- **AS-9.** Surfaced at P1.1 while verifying RF-2 (the shim-signin-vs-web-login lockout lever): the reason RF-2 is only LATENT is that `defaultRateLimiter` (`packages/api-routes/src/rate-limit/rate-limiter-registry.ts`) checks `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` at boot and, finding neither set in the platform Vercel project, falls back to `createNoopRateLimiter()` — every `RATE_LIMIT_TIER` check passes. So today the whole platform (web login, password-reset, the new shim signin) is unthrottled in prod. This is bigger than apex-sunset (it's the platform's standing security posture) but it makes the ratified R2 brute-force bound vacuous in prod, so it rides here until the owner decides. Wiring Upstash is now safe because RF-2's `shim-auth:` namespace stops the shim from sharing the web login's bucket.
- **AS-12.** The read path (`get-program.ts`) routes on `identity.legacyPlanId`/`legacyLevelId` — values MIRRORED into `MobileLegacyIdentity` at the P2.1 import — where the live legacy re-reads plan/level per request. `/program` is the first endpoint where a mirror drift yields the WRONG TRAINING CONTENT (a General athlete served the wrong level, or an Individual↔General mis-route) rather than a stale profile field. Inherent to ADR-0043 (we mirror identity precisely so the foreign backend can be deleted), surfaced by the P1.3 review (RF-6). The P2.2 identity-reconciliation gate MUST assert plan/level fidelity for every linked athlete, and P2.1's import must copy them exactly. The app does not let an athlete self-change plan/level today (coach-assigned), so no in-app drift path exists; if that ever changes, the mirror needs a refresh path.
