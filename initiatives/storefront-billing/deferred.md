## Detail on the live ones

- **SB-1.** Partly answered by the 0.2 spike (2026-09-25): test mode covers `invoice`, `wallet/payment` and `subscription/*`; the subscription status values seen are `pending`, `active`, `cancelled`, `removed`; `subscription/list` and `/payments` take RFC 3339 `dateFrom`/`dateTo`. Still open: `webHookUrls` field names, the recurring-charge and subscription webhook payloads, a declined-charge simulation. The new docs site SSRs only the top level of a request schema (`webHookUrls object {` and the 200 body are collapsed), the old Redoc spec at `api.monobank.ua/docs/acquiring.html` predates the subscription section, and the download button for the AI-skill archive is JS-only. What is already verified is in `monobank-notes.md`.
- **SB-11.** Verified in code: `get-program.ts` resolves the day from `MobilePublishedDay` via the link (`GENERAL` by `legacyLevelId`, `INDIVIDUAL` by `legacyUserId`); no enrollment is consulted. The gate (D-7) therefore needs the 4.1 script to enroll each imported athlete into the plan of their level's GENERAL link before X, and the shim's gate treats "no enrollment on the linked plan" as OPEN until then (same law as the web: no grant object = coach-granted). Denys's OWN app identity (legacy id 2, legacy ADMIN role, a CREATE row on a different address than his coach account) must be covered by the 4.1 grant as a permanent comp (D-11 Q8: «никому, кроме твоего аккаунта») — otherwise X closes the coach's own phone.

- **SB-25, the deferred set of the 0.3 internal review** (owner ruling 2026-09-28; almost all of it is older than the PR):
  - RF-7 — `formatPeriod` throws on a unit it does not know; reachable only when the deployed code and the schema disagree.
  - RF-9 — `clearAll` has no automated test; one would wipe the test database the suite shares. The 0.3 proofs executed it by hand.
  - RF-13 — the admin price form shows zod's raw "Expected number, received nan".
  - RF-21 — the seed refuses production by `NODE_ENV` alone.
  - RF-29 — the pricing card throws when the currency is undefined; both views seed it.
  - RF-30 — two concurrent first-price updates create two active prices.
  - RF-31 — updating a product that does not exist answers 400 instead of 404, and a price update on a soft-deleted product succeeds.
  - The marketing app has no test project; creating one touches the root vitest config.
  - The admin dashboard line rounds the amount with `toFixed(0)`: 999 cents read as `10 USD/month` (independent review, breaker; older than the PR).
