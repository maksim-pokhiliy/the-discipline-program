## Gotchas a resuming session must know

- **The iOS shim is Billing-blind by dep-cruiser** (`api-server-mobile-compat-no-cms-billing`); so are LMS and Coaching. The ONLY door is `authz/` (`resolveEnrollmentAccess`, D-7). Do not add a Billing import anywhere else.
- **The app's wire traps are sacred** (apex-sunset charter): the soft wall is a normal 200 program DTO with text; never a new status, never `isRestDay:false` with a null program, never a link (Apple 3.1.1).
- **ADR-0008 (singleton subscription) and ADR-0014 (Stripe) are superseded by ADR-0044** — do not design around `userId @unique` or `stripe*` columns; the W0 migration removes them.
- **The roadmap's "second paying coach" trigger is superseded** by Denys's 2026-09-22 pull — do not re-litigate "billing is post-launch".
- **Existing iOS athletes have no `PlanEnrollment`** (SB-11): the gate must treat "no grant object" as OPEN until the 4.1 grant, or the cutover kicks everyone.
- **Denys has no mono business account yet** (SB-5): dev/preview run on the owner's test token; only P4 waits on him.
- **Every local run targets the Docker stack (D-14).** Dev servers → `tdp`, `task test:api` → `tdp_test`, `pnpm db:migrate` → `tdp_shadow`; the Neon lines in the env files are commented and stay that way. `task stack:reset` wipes local data; `stack:down` keeps it.
- **Mono webhooks (verified):** sign over the RAW body bytes; a merchant-initiated charge fires `processing` then `success` ~50 ms apart (order-tolerant handler); invoice creation fires `created`; expiry fires nothing — reconcile by polling. Fixtures in `spike/fixtures/`.
- **W0 is on every database:** production, dev Neon, and `tdp` / `tdp_test` of the local stack (`tdp_test` was recreated on 2026-09-28). `Product.stripeProductId`, `Price.interval` and `Price.stripePriceId` exist in the database and in `schema.prisma` but carry `@ignore`: the generated client does not know them. Do not remove `@ignore` and do not read them through raw SQL.
- **The api-server suite is re-runnable (SB-20, PR #404):** twice on one database, in any file order, every table as it was. The test setup refuses a `DATABASE_URL` that is not a test database (postgres scheme, loopback host, one path segment, a name `test` or `*_test`), counts every table before and after each file, and checks the head-coach holders. `task test`, `task test:watch` and `task test:coverage` pass `tdp_test`; a bare `pnpm test` is refused. Every api-server test file opens the database now (about 2 min 30 s for the suite). The rules for a new test file: `docs/runbooks/local-stack.md` § Writing an api-server test.
- **A migration that production needs before the code is dispatched from the PR branch** (`docs/runbooks/db-migrate-dispatch.md`); after the dispatch its file is frozen.
- **The project hook `PROD-GUARD` refuses `Edit` / `Write` on `prisma/migrations/`, lock files and CI workflows, always.** An executor creates a new migration file through the shell; every change to an existing one needs the owner's explicit word in the planner's session, and the planner then makes it.
- **A migration file carries no transaction control (verified 2026-09-28).** Prisma applies a file atomically by itself; an explicit `BEGIN` masks the real error and the inner pair Prisma emits around an enum swap splits the file in two. Strip them by hand.
- **`prod_snap` in the local stack is a restore of production** (dump `~/tdp-prod-2026-09-28.dump`, owner-authorized). Rehearse on a clone (`createdb -T prod_snap <name>`), never on the snapshot itself; it is never the `DATABASE_URL` of a dev server or a test run.
- **Port 3002 belongs to another project's Django dev server on the owner's box** — for checks admin runs on 3012 (`pnpm --filter admin exec next dev --port 3012`).
