## Detail on the load-bearing ones

### T0-1 — create-only (the headline)

The compose algebra is create-only end-to-end: `emptyBlockProgram` seed (`compose-editor-drawer.tsx:80`) + `composeRootToCreatePlan` with no inverse + a draft container type carrying only a synthetic `NodeId` (`compose-tree.types.ts:49`) + zero `Composition→ComposeProgram` adapter (repo grep empty). The wire to UPDATE composition exists (`use-persist-compose-cascade.ts:54` fires `updateSchema` with composition, but ONLY inside `wireArrangements` during the create cascade). So the blocker is the **data-mapping layer + an edit entry point**, not the persistence API. Until the adapter exists, any "edit axes" feature is blocked at data-mapping, not at the button.

### T0-2 — program/slot (SHIPPED 2026-06-07, 0b; D-ONTOLOGY)

The board's three shapes ((i) fat VO as `rowKind` payload, (ii) fat VO as 5th axis, (iii) nested sub-schemas) were all premised on the fat VO being the home. The owner's four-projection ruling reframed it: a "stage" is **one `EXERCISE` row** (per-stage `load`/`reps` already on the row; `addRow`/`reorderChildren` already exist) — so stages need no new container/payload, only authoring. EMOM is already nested-window (Gauntlet B); `slotSpec` is redundant. What's genuinely missing is **classification**, ruled needed by the owner. Home: a **thin `programKind` field on `composition`** (group-level classifier; M1 over a marker-row M2 — see `decisions.md` D-ONTOLOGY for the four-projection + D-LADDER-precedent reasoning), with **both fat VOs DELETED**. Shipped on `feat/compose-program-kind` (7 feature commits): `composition += programKind`, selector + card badge, create/edit round-trip (keystone from the edited draft), seed re-author. Disposed T3-CT-1 + the seed flattening. The Gate-A composition change is now IN.
