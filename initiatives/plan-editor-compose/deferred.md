## Detail on the live ones

### QA-001 (CLOSED — S1, PR #241)

**Shipped in S1 exactly as designed:** `assertComposeTreeValidForWrite` (400 `BadRequestError`, reusing the pure `projectSchemaWithBody` + a shared `buildSchemaWithBody`) hooked into schema-row create (in-tx, post-insert re-fetch, rolls back), schema-row update (defensive), and schema update-of-composition (pre-write). The three pinned `week/admin.test.ts` tests flipped/re-pointed + a Hook-3 integration test added — api-server **813/813** green. Original finding below for the trail.

The ladder-collision invariant is enforced ONLY at read today (`assertComposeTreeValid` in `compose-projection.mapper.ts`, throws 500). The sibling `schema-row/admin.ts` create is unguarded, the seed ships an ATOMIC `repetition:ladder` container (`BLOCK_LADDER_DESC_WK1_MON`), so a coach POSTing an `INNER_LADDER_MARKER` row to it bricks the whole week on the next read. Design: a 400-throwing sibling of `assertComposeTreeValid` (reuse the pure `projectSchemaWithBody`, `safeParse`, throw `BadRequestError`) hooked into schema-row create (inside the existing tx, post-insert re-fetch + project) + schema-row update + schema update-of-composition (pre-write construct-and-validate). Flip `week/admin.test.ts:766-789` from read-500 to write-400. Full design in `10-4-recon.md` §WRITE-GUARD.

### DR-1 (CLOSED — S2 Run-1, PR #242) — read-shape widen + composition-only handler enable

S1 chose option (b) ([[D-10.4-S1-RS]] in `decisions.md`): the read contract `schemaSchema.{kind,archetypeId,archetypeParams}` stays NON-NULL, and `mapToSchema` narrows the now-nullable Prisma columns with a 500 DbCorruption guard. Consequence: a composition-only `Schema` cannot round-trip — the contract accepts the create (triad optional), it persists, but the read 500s (D-10.4-S1-INT, the accepted poison-intermediate). **S2 MUST, before/with shipping the first composition-only writes:**

1. widen `schemaSchema` + `SchemaShape.{kind,archetypeId,archetypeParams}` to nullable;
2. drop the `mapToSchema` narrow-guard (let it return null);
3. null-guard the ~6 platform read sites (`schema-card.tsx`, `schema-card-head.tsx`, `schema-card-meta.tsx`, `schema-editor-modal.tsx` ×2, `format-schema-header.ts`) + the `schemaSchemaWithInvariants` `value.kind` reader;
4. enable the composition-only path in `lmsSchemaApi.create` (S1 has NO handler gate — the poison is API-only-reachable; S2 makes composition-only authoring first-class).

All four land together so the poison window closes exactly when composition-only authoring opens.
