# mobile-publish — deferred (carry-forwards / WARNINGs)

Status: `OPEN` / `SCHEDULED` / `CLOSED` / `DROPPED`.

- **MP-1 — Individual identity picker.** OPEN (P2). The coach links a platform enrollment → a legacy `user_id` chosen from `GET /user?userPlanId=2`. No automatic matching; manual + coach-driven (D-2/D-3).
- **MP-2 — Bake resolved weights for Individual.** OPEN (P2-optional). For an Individual link we know the athlete's 1RMs → can render resolved kg into the text instead of "%". General can't (shared by level).
- **MP-3 — Delete-propagation.** OPEN (P3). If a coach deletes / un-publishes a day, do we DELETE the legacy row or leave it? Default lean: an explicit un-publish DELETEs; a plain platform edit never deletes.
- **MP-4 — Token-expiry UX.** OPEN (P3). Legacy JWT TTL = 1 month, no refresh endpoint → store expiry, prompt reconnect before it lapses; a publish on an expired token must fail gracefully (re-connect CTA).
- **MP-5 — `Week.startDate` = Monday assumption.** CLOSED (P1a — VERIFIED). Research confirmed `Week.startDate` is non-nullable + always a UTC-midnight Monday (triple-guaranteed); the projection uses `sessionAbsoluteDateFromParts(week.startDate, day.dayOfWeek)` (MONDAY=0…SUNDAY=6), UTC-serialized via `utils/date-param.ts`.
- **MP-6 — Training-level name drift.** MITIGATED / standing rule (P1a). `GET /trainingLevel/all` is always read live (the `training-levels` endpoint proxies it; the gated T16 asserts level Pro=id 2 read live); ids/names are never hardcoded. Keep reading live in P2 (the Individual athlete picker).
- **MP-7 — Publish-endpoints placement vs dep-cruiser.** CLOSED (P1a — D-6). Connector lives in `endpoints/coaching/mobile-publish/` reading lms read-models (Coaching→LMS allowed); the legacy client in `infrastructure/legacy-mobile/`. No new context, no new rule; `pnpm dep:check` clean.
- **MP-8 — No legacy unique constraint on (key, date).** OPEN (mitigated, P1a). Our-side `upsert` on `(linkId, scheduledDate)` is race-free; the legacy 409→PUT fallback + the overwrite-guard re-decide (D-9) converge concurrent publishes without clobbering coach-authored days. Residual: the legacy `findByTrainingLevelIdAndDate` check is non-atomic (no DB unique) → a true TOCTOU could still double-insert on the legacy side — un-closeable from our side (D-1). Documented limitation; no distributed lock in P1a.
- **MP-9 — Token encryption key rotation.** OPEN (P3). D-7 uses a single `MOBILE_PUBLISH_ENCRYPTION_KEY`; rotating it invalidates all stored tokens → every coach reconnects (acceptable for a handful of coaches). A future envelope-encryption / key-version-prefix scheme would rotate without mass reconnect.
- **MP-10 — Week-publish resilience / latency.** OPEN (P3). A week publish does up to 7×(GET+write) sequential legacy calls with no overall deadline → a slow legacy could approach the serverless function limit. Per-day failures are now isolated (`failed` action) and an idempotent re-publish recovers (already-done days → `skipped`); P3 could batch/parallelize or background the publish + add a per-call budget. (The design's contingent "MP-10 = consolidate a copied renderer" never applied — D-8 chose the true-SSOT extraction (b), so no copied renderer exists.)
- **MP-NORTH-STAR — Repoint iOS at the platform API.** OPEN (future initiative). Build legacy-contract-compatible endpoints in the platform, migrate the iOS baseURL + accounts, retire the Java backend. ADR-0005/0020 anticipate it. Out of THIS initiative's scope (D-1).
