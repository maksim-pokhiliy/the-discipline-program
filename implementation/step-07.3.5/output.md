## Принятые решения

**D-1: Inline-fix `packages/api-server/src/endpoints/lms/day/admin.ts` (consumer-miss).**
После расширения `SessionWithRelations` (Prisma тип в `day.mapper.ts`) полем `blocks: BlockWithLabelsRelation[]` второй consumer `mapToDaySlot` (`lmsDayMetadataApi.setLabel` + `.setNotes` в `lms/day/admin.ts`) сломал check-types на `Property 'blocks' is missing` — pre-existing endpoint вызывает `mapToDaySlot(dayOfWeek, day)` где `day` берётся из `tx.day.upsert({include: DAY_INCLUDE})`, а `DAY_INCLUDE` const не включал blocks. Это classic `[[planner-consumer-pattern-read]]` miss — § 0.A grep map не enumerated `mapToDaySlot` consumers. Решение принято через `AskUserQuestion` (option A "Inline-fix" — Recommended): `DAY_INCLUDE` расширен идентичной структурой как week/admin.ts (mirror pattern, 6th file edit). Scope creep с 5 → 6 файлов; § 5.1 acceptance criterion N/A → INFO. Альтернативы (Abort+re-plan / type-isolate с дублирующим mapper) отклонены user'ом как worse (re-plan = extra round-trip; type-isolate = code duplication + breaks planner's single-helper design).

**D-2: Prisma `Json?` null typing в test fixtures.**
Первичная попытка задать `intensity: null, timeCap: null, notes: null` в `cleanupRaw.block.create({data: {...}})` для D-1 block-second test row упёрлась в Prisma 6 typing (`Json?` ожидает `InputJsonValue | NullableJsonNullValueInput`, не direct `null`). Решение: omit'ить nullable поля целиком — DB defaults дают `intensity=null, timeCap=null, notes=null`. Pure inline fix внутри scope. Альтернатива (`Prisma.JsonNull` literal) добавила бы import — без выигрыша.

**D-3: Barrel re-export `mapToSessionWithLabelAndBlocks`.**
Prompt § 0.3 directive — "skip barrel export". Helper не добавлен explicit'но в `mappers/lms/index.ts`, но pre-existing `export * from "./day.mapper"` автоматически re-exports новую функцию. Альтернатива (convert index.ts к named explicit re-exports) — out-of-scope refactor; review-light agent INFO-002 flagged как acceptable matched-existing-convention. Принято без изменений: новая функция технически доступна downstream, но Step 7.3.5/7.4 её не consume (api-server-internal).
